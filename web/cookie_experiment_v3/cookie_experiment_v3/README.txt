Cookie Experiment v3

- 12 independent mock websites with intentionally different background layouts/content.
- Cookie banner position, copy, font, size and button styling are held constant.
- EASY: first layer has Reject All / Cookie Settings / Accept All.
- HARD: first layer has Cookie Settings / Accept All.
- Both conditions use the identical settings modal with Reject All and Save Current State.
- Save Current State classifies the final state as REJECT_ALL / CUSTOM / ACCEPT_ALL based on toggles.
- Supabase project Cookie_banner is already connected.
- Server-side assignment caps ACTIVE assignments at EASY 25 and HARD 25 (50 total).
- Participant research codes are generated by the database (P0001...).
- Site order is randomized per participant; trial position remains 1-12.
- Each trial is written immediately to Supabase. Pre/post surveys are linked by participant UUID.

IMPORTANT
1. The 25/25 cap is based on assigned participants (STARTED or COMPLETED), not completed-only participants. This prevents overbooking. If someone truly drops out, mark that participant DROPPED in Supabase before recruiting a replacement.
2. The publishable key in config.js is intentionally a browser-safe Supabase key. Never put a secret/service_role key in browser code.
3. IUIPC-8 Korean text in this prototype is a working research translation, not claimed as a validated Korean translation. Verify translation/back-translation before the main study.
4. Open index.html through a web server/hosting environment. For local testing: python -m http.server 8000 then open http://localhost:8000.
5. Researcher data inspection should be done in the Supabase dashboard; participants have no table SELECT permission.
